1Complexity and the learning curve slides 2–10

Complexity = flexibility: the complexity of a classifier is its ability to fit any data distribution. On the banana set, a straight line cannot follow the curved classes (too simple), while a very flexible boundary can wrap around every training point, including the noise (too complex).

The learning curve

Plot error against the number of training objects N. Two curves matter:

  • True error \(\varepsilon\): error on new data from the same distribution (what you care about).
  • Apparent error \(\varepsilon_A\): error on the training set itself. It is too optimistic: the classifier was fitted to exactly those objects.

As N → ∞ both converge to the same asymptotic error, the best this model family can do.

Key rule (slide 8)

Choose the complexity according to the available training set size. Complex classifiers pay off with enough data; with few objects they overtrain, so use a simple classifier.

So the questions for the rest of the lecture are: how do we measure complexity, and how do we control it?

2Reducing complexity in normal-based classifiers: regularisation slides 12–20

Normal-based classifiers (QDC, LDA/Fisher) estimate a mean \(\boldsymbol\mu\) and covariance \(\Sigma\) and need the inverse \(\Sigma^{-1}\) for the Mahalanobis distance \((\mathbf x-\boldsymbol\mu)^T\Sigma^{-1}(\mathbf x-\boldsymbol\mu)\).

The problem: too few points

With 2 points in 2D, all variation lies along one line, so the estimated covariance has zero variance in the other direction:

\[\hat\Sigma=\begin{bmatrix}5&0\\0&0\end{bmatrix}\quad\Rightarrow\quad \hat\Sigma^{-1}=\begin{bmatrix}\tfrac15&0\\0&\tfrac{1}{0}\end{bmatrix}\ \text{(undefined!)}\]

Fix: add a bit of artificial noise, i.e. a small \(\lambda\) on the diagonal:

\[\hat\Sigma+\lambda I=\begin{bmatrix}5+\lambda&0\\0&0+\lambda\end{bmatrix}\quad\Rightarrow\quad (\hat\Sigma+\lambda I)^{-1}=\begin{bmatrix}\tfrac{1}{5+\lambda}&0\\0&\tfrac{1}{\lambda}\end{bmatrix}\ \text{(well defined)}\]

Quadratic classifier (QDC)

\[g_i(\mathbf x)=-\tfrac12\log\det\Sigma_i-\tfrac12(\mathbf x-\boldsymbol\mu_i)^T\Sigma_i^{-1}(\mathbf x-\boldsymbol\mu_i)+\log p(\omega_i)\]
  • QDC estimates one \(\Sigma_i\) per class. If the number of objects (per class) is ≤ the dimensionality p, \(\Sigma_i^{-1}\) does not exist and the classifier is not defined.
  • Regularisation solves it: \(\tilde\Sigma_i=\Sigma_i+\lambda I\).
  • With very large regularisation \(\lambda\to\infty\) (and equal priors) you get the nearest mean classifier. Why: \(\tilde\Sigma_i\approx\lambda I\) for every class, so the Mahalanobis term becomes \(\|\mathbf x-\boldsymbol\mu_i\|^2/\lambda\) and the \(\log\det\) terms are identical for all classes. Only the Euclidean distance to the mean is left.

So λ is a complexity knob: λ = 0 is full QDC (most flexible); λ → ∞ is nearest mean (least flexible).

LDA / Fisher classifier

\[f(\mathbf x)=(\boldsymbol\mu_B-\boldsymbol\mu_A)^T\hat\Sigma^{-1}\mathbf x + C\]

Same phenomenon, but because the covariance matrix is averaged over the two classes (pooled), the peak appears at a smaller sample size. Instead of regularisation, the pseudo-inverse of the covariance matrix is often used.

Needed for Ex 1.3 · what pr.fisherc actually does

The prtools implementation (in prtools/prtools.py) computes the within-class scatter \(S_W=S_A+S_B\), adds a tiny ridge, and then:

\[\mathbf w = (S_W+10^{-5}I)^{-1}(\mathbf m_B-\mathbf m_A),\qquad \text{boundary: } \mathbf w^T\mathbf x = \tfrac12(\mathbf m_A+\mathbf m_B)^T\mathbf w-\log\tfrac{N_B}{N_A}\]

So Fisher uses all objects (through the class means and the scatter), and the boundary passes (almost) through the midpoint of the two class means. If the data has zero spread in some direction, the \(10^{-5}\) ridge makes \(\mathbf w\) huge along that direction. That matters for the tiny data sets in Ex 1.1 and 1.3.

The general recipe: a regulariser

Optimising purely the training error, \(\min_\theta \varepsilon_A(\theta)\), can overfit. Punish too-flexible solutions with a regulariser \(\Omega(\theta)\) that measures flexibility:

\[\min_\theta\ \underbrace{\varepsilon_A(\theta)}_{\text{training error}}+\underbrace{\lambda}_{\text{reg. parameter}}\ \underbrace{\Omega(\theta)}_{\text{regulariser}}\]

Changing λ changes the complexity. The SVM in §5–8 has exactly this shape: training error (slack) plus \(\|\mathbf w\|^2\).

3How to characterise complexity: is it the number of parameters? slides 21–28

A first guess: complexity = number of free parameters. In 1D, a classifier with N thresholds has N parameters, and more thresholds can carve the line into more regions, so it gets more complex. So far so good.

Counter-example: \(f(x)=\operatorname{sign}(\sin(\omega x))\) has one parameter ω, yet by tuning the frequency you can (almost) always separate red from blue. Try it:

Conclusion

The number of parameters is not a good complexity measure. Changing a regularisation parameter changes complexity, but we want a direct measure: the VC-dimension (Vapnik–Chervonenkis).

4VC-dimension and bounding the true error slides 29–34

Definition

The VC-dimension h of a classifier is the largest number of vectors h that can be separated (shattered) in all \(2^h\) possible ways (all labelings).

Fine print: it is enough that one configuration of h points can be shattered (not every configuration), and no configuration of h+1 points can.

VC-dimension of a linear classifier

\[h=p+1\qquad(p=\text{dimensionality})\]

Why care? The bound on the true error

Only for very few classifiers is h known. But when you know h, you can bound the true error. With probability at least \(1-\eta\):

\[\varepsilon\ \le\ \varepsilon_A+\frac{\mathcal E(N)}{2}\left(1+\sqrt{1+\frac{\varepsilon_A}{\mathcal E(N)}}\right),\qquad \mathcal E(N)=4\,\frac{h\big(\ln(2N/h)+1\big)-\ln(\eta/4)}{N}\]

(Vapnik, Statistical Learning Theory, 1998. Some texts write \(4\varepsilon_A/\mathcal E\) under the root; for \(\varepsilon_A=0\) the two are the same.)

  • \(\mathcal E(N)\) grows with h and shrinks with N: what matters is roughly N/h.
  • When h is small, the true error is close to the apparent error. That is the whole motivation for the SVM: keep h small.
Is this bound practical? (slide 34)
  • No, it is very loose.
  • It assumes the worst case: objects could be labelled randomly.
  • In practice features are chosen so that classes cluster nicely, so real errors are far below the bound.

Its value is conceptual: to generalise well, make h small relative to N.

5Reducing h for linear classifiers: the maximum margin slides 35–38, 46–48

A free hyperplane has h = p + 1. We can lower h by constraining the hyperplane. Assume the data is linearly separable and demand that the classifier output is at least 1 in magnitude on every training object:

\[\mathbf w^T\mathbf x_i+b\ \ge\ +1\ \ \text{for } y_i=+1,\qquad \mathbf w^T\mathbf x_i+b\ \le\ -1\ \ \text{for } y_i=-1\qquad\Longleftrightarrow\qquad y_i(\mathbf w^T\mathbf x_i+b)\ge 1\]

This fixes the scale of w (otherwise w and 2w give the same line). The resulting hyperplane is called the canonical hyperplane: the closest objects sit exactly at \(\mathbf w^T\mathbf x+b=\pm1\).

The VC-dimension of a canonical hyperplane

\[h\ \le\ \min\!\left(\left\lfloor\frac{R^2}{\rho^2}\right\rfloor,\ p\right)+1\]

So to find a classifier with a small VC-dimension: (1) minimise the dimensionality p, (2) minimise the radius R, (3) maximise the margin ρ. Point 3 is the one we can optimise directly.

From "maximise margin" to "minimise ‖w‖"

The distance from a point \(\mathbf x\) to the hyperplane \(\mathbf w^T\mathbf x+b=0\) is \(\dfrac{|\mathbf w^T\mathbf x+b|}{\|\mathbf w\|}\). The closest points have \(|\mathbf w^T\mathbf x+b|=1\), so they lie at distance \(1/\|\mathbf w\|\) on each side and the full margin width is \(2/\|\mathbf w\|\). Hence maximising the margin = minimising \(\|\mathbf w\|\). (The slide writes \(\|\mathbf w\|^2=2/\rho^2\). The constant depends on whether ρ means the half- or full width; only \(\|\mathbf w\|\propto 1/\rho\) matters.)

The support vector classifier (hard margin, primal form)
\[\min_{\mathbf w,b}\ \tfrac12\|\mathbf w\|^2\qquad\text{s.t.}\qquad y_i(\mathbf w^T\mathbf x_i+b)\ \ge\ 1\quad\forall i\]

Geometric shortcut (great for pen-and-paper, Ex 1.1): for separable data, the max-margin boundary is the perpendicular bisector of the two closest points of the two classes' convex hulls. Those closest points can be data points or points on a hull edge.

A 1D picture of "minimum norm w" (slides 46–48)

Use \(y=\operatorname{sign}(wx+w_0)\) on four 1D objects: x = 1 (class −1) and x = 2, 3, 4 (class +1). Plot the output \(f(x)=wx+w_0\) instead of the label. The constraints say: f(1) ≤ −1 and f(2), f(3), f(4) ≥ +1. Many lines satisfy them; the SVM picks the least steep one (minimum |w|).

6Solving it: constrained optimisation, the dual and support vectors slides 39–50

Constrained optimisation in one picture

Lagrangian of the SVM (slides say "solving w.r.t. w and b is simple"; here are the steps)

One multiplier \(\alpha_i\ge0\) per constraint:

\[L(\mathbf w,b,\boldsymbol\alpha)=\tfrac12\|\mathbf w\|^2-\sum_{i=1}^N\alpha_i\big[y_i(\mathbf w^T\mathbf x_i+b)-1\big]\]

Set the derivatives to zero:

\[\frac{\partial L}{\partial\mathbf w}=0\ \Rightarrow\ \boxed{\mathbf w=\sum_{i=1}^N\alpha_iy_i\mathbf x_i}\qquad\qquad \frac{\partial L}{\partial b}=0\ \Rightarrow\ \boxed{\sum_{i=1}^N\alpha_iy_i=0}\]

Substituting back eliminates w and b and leaves the dual problem in the α's only (slide 43):

SVM dual (a quadratic programming problem)
\[\max_{\boldsymbol\alpha}\ \sum_{i=1}^N\alpha_i-\frac12\sum_{i,j=1}^N y_iy_j\,\alpha_i\alpha_j\,\mathbf x_i^T\mathbf x_j\qquad\text{s.t. }\ \alpha_i\ge0\ \ \forall i,\qquad \sum_{i=1}^N\alpha_iy_i=0\] \[f(\mathbf z)=\mathbf w^T\mathbf z+b=\sum_{i=1}^N\alpha_iy_i\,\mathbf x_i^T\mathbf z+b\]

It is convex, so there is one global optimum (no local minima, unlike a neural network).

Support vectors

The optimum satisfies complementary slackness (the KKT condition): \(\alpha_i\,[\,y_i(\mathbf w^T\mathbf x_i+b)-1\,]=0\). So for every object either:

  • \(y_i f(\mathbf x_i)>1\): it is beyond the margin, so \(\alpha_i=0\) and it has no influence, or
  • \(\alpha_i>0\): it lies exactly on the margin, \(y_if(\mathbf x_i)=1\). These are the support vectors.
  • The solution \(\mathbf w=\sum\alpha_iy_i\mathbf x_i\) is expressed in terms of objects, not features.
  • Only a few weights become non-zero (a sparse solution).
  • b follows from any support vector s: \(b=y_s-\mathbf w^T\mathbf x_s\).
Handy checks for pen-and-paper SVMs Ex 1.1
  • \(\sum_i\alpha_iy_i=0\): the α-mass is balanced between the classes.
  • For a hard margin, \(\sum_i\alpha_i=\|\mathbf w\|^2\). (Multiply each active constraint by \(\alpha_i\) and sum.)
  • Every support vector satisfies \(y_i(\mathbf w^T\mathbf x_i+b)=1\) exactly; every other object gives a value \(>1\).

Error estimate from the training set alone

\[\varepsilon_{LOO}\ \le\ \frac{\#\text{support vectors}}{N}\]

Why: in leave-one-out, removing a non-support vector doesn't change the solution, and that object was correctly classified beyond the margin, so it causes no error. Only removing a support vector can produce a mistake.

High-dimensional feature spaces

The classifier is determined by objects, not features. So it tends to perform very well in high-dimensional spaces: the number of α's is N, whatever p is.

8Limitation 1: overlapping classes → slack variables slides 51–56

The SVM so far has two limitations: (1) the data must be separable, (2) the decision boundary is linear. This section fixes (1); the kernel trick fixes (2).

Weaken each constraint with a slack variable \(\xi_i\ge0\), one per object:

Soft-margin SVM
\[\min_{\mathbf w,b,\boldsymbol\xi}\ \|\mathbf w\|^2+C\sum_{i=1}^N\xi_i\qquad\text{s.t.}\quad\begin{aligned}&\mathbf w^T\mathbf x_i+b\ge+1-\xi_i&&\text{for }y_i=+1\\&\mathbf w^T\mathbf x_i+b\le-1+\xi_i&&\text{for }y_i=-1\\&\xi_i\ge0&&\forall i\end{aligned}\]
Slack valueWhere is the object?
\(\xi_i=0\)On or beyond its own margin line (correct, no penalty)
\(0<\xi_i\le1\)Inside the margin but on the correct side of the boundary
\(\xi_i>1\)On the wrong side of the boundary: a training error

The trade-off parameter C

  • C has to be defined beforehand. It weighs the training error (\(\sum\xi_i\)) against the structural error (\(\|\mathbf w\|^2\), i.e. complexity/margin).
  • Large C: violations are expensive, so you get a narrow margin that tries hard to classify every training object. Erroneous objects (outliers) still have a large influence (slide 56: with C = 1000 the boundary tilts towards the outliers).
  • Small C: a wider margin that tolerates violations (more regularisation).
  • Choose C by cross-validation.
Extra (not on the slides, but useful with sklearn/prtools)

In the dual, the only change slack makes is a box constraint: \(0\le\alpha_i\le C\). Objects with \(\alpha_i=C\) are inside the margin or misclassified. If all α's of the hard-margin solution are already ≤ C, the soft-margin solution is identical. That is why svc(a,('linear',1,1)) already reproduces the hard-margin answers in Ex 1.1.

9Limitation 2: linear boundary → the kernel trick slides 57–66

Observation: the data only enters through inner products

Look again at the dual and the classifier:

\[\max_{\boldsymbol\alpha}\sum_i\alpha_i-\frac12\sum_{i,j}y_iy_j\alpha_i\alpha_j\,\underbrace{\mathbf x_i^T\mathbf x_j}_{\text{inner product}}\qquad f(\mathbf z)=\sum_i\alpha_iy_i\,\underbrace{\mathbf x_i^T\mathbf z}_{\text{inner product}}+b\]

"Magic": all operations are inner products between objects. Now suppose we had a transformation \(\Phi(\mathbf x)\) that makes the data linearly separable. We just replace every \(\mathbf x\) by \(\Phi(\mathbf x)\).

Example transformation (slide 59)

\[\mathbf x=(x_1,x_2)\ \longmapsto\ \Phi(\mathbf x)=(x_1^2,\ x_2^2,\ \sqrt2\,x_1x_2)\]

The polynomial kernel: the inner product is cheap (slide 60)

\[\Phi(\mathbf x)^T\Phi(\mathbf y)=x_1^2y_1^2+x_2^2y_2^2+2x_1x_2y_1y_2=(x_1y_1+x_2y_2)^2=(\mathbf x^T\mathbf y)^2\]

You never need to build Φ: squaring the ordinary inner product gives the inner product in the 3-D mapped space.

The kernel trick

If we introduce a magic Φ, we can just as well introduce a magic kernel function \(K(\mathbf x,\mathbf y)=\Phi(\mathbf x)^T\Phi(\mathbf y)\) and forget about Φ:

Kernelised SVM
\[\max_{\boldsymbol\alpha}\sum_{i}\alpha_i-\frac12\sum_{i,j}y_iy_j\alpha_i\alpha_j\,K(\mathbf x_i,\mathbf x_j)\quad\text{s.t. }\alpha_i\ge0\ (\le C),\ \ \sum_i\alpha_iy_i=0\] \[f(\mathbf z)=\sum_{i=1}^N\alpha_iy_i\,K(\mathbf x_i,\mathbf z)+b\]
  • Kernel trick = replace all inner products by one function K.
  • It implicitly maps the data to a (usually) high-dimensional feature space.
  • The practical computational cost does not change (apart from evaluating K).
  • Recipe for any algorithm: write it using only inner products \(\mathbf x^T\mathbf y\), then swap in \(K(\mathbf x,\mathbf y)\). Ex 2.2

  • pr.svc's polynomial kernel is actually sklearn's \((\gamma\,\mathbf x^T\mathbf y+1)^d\) with \(\gamma=1/p\).

What the RBF width does

\(f(\mathbf z)=\sum_i\alpha_iy_iK(\mathbf x_i,\mathbf z)+b\) is a weighted sum of Gaussian bumps centred on the support vectors.

σ small

Each bump is very narrow, so the boundary wraps tight "islands" around individual training objects: very complex. Training error is 0 but the model overfits, almost every object becomes a support vector, and far from the data \(f(\mathbf z)\approx b\), so everything falls into one class.

σ large

The bumps are very wide and the boundary is smooth, close to linear: simple. It underfits curved classes like the banana set.

Advanced kernels (slide 66)

People design kernels for specific applications: tangent distance kernels (rotation/scaling invariance for digits), string matching kernels (DNA/protein sequences), Fisher kernels (use knowledge of class densities), Hausdorff kernels (compare image blobs). Any K works as long as it is a valid inner product in some space, i.e. every Gram matrix \([K(\mathbf x_i,\mathbf x_j)]\) is positive semi-definite (Mercer's condition).

10Kernelising other classifiers: nearest mean ↔ Parzen Ex 2.2 Ex 2.3

The kernel trick isn't SVM-specific. Any method that touches the data only through inner products can be kernelised. The assignment does this for the nearest mean classifier (NMC). The ingredients:

  • Distances become inner products: \(\|\mathbf a-\mathbf b\|^2=\mathbf a^T\mathbf a-2\mathbf a^T\mathbf b+\mathbf b^T\mathbf b\).
  • A mean is a sum of objects: \(\mathbf m_C=\frac1{N_C}\sum_i\mathbf x_i^C\), so inner products with a mean become averages of inner products with objects.
  • Gaussian kernel facts: \(K(\mathbf x,\mathbf x)=1\) for every x, and \(\frac1{N_C}\sum_iK(\mathbf x,\mathbf x_i^C)\) is exactly a Parzen density estimate of class C (up to the constant \((2\pi\sigma^2)^{-p/2}\)).

Putting these together (full derivation in Ex 2.2), the squared distance to a class mean in kernel space is

\[d_C^2(\mathbf x)=\underbrace{K(\mathbf x,\mathbf x)}_{=1}-2\,\underbrace{\frac1{N_C}\sum_iK(\mathbf x,\mathbf x_i^C)}_{\hat p_C(\mathbf x)\ \text{(Parzen)}}+\underbrace{\frac1{N_C^2}\sum_{i,j}K(\mathbf x_i^C,\mathbf x_j^C)}_{c_C\ \text{(constant per class)}}\]

So "nearest kernel mean" means "largest Parzen density, corrected by a per-class constant". The widget makes this concrete in 1D. Class A is spread out and class B is compact, so \(c_A\neq c_B\):

Relation to the SVM (useful for Ex 2.3b)

Write the Parzen classifier (equal priors) as a decision function: \(g(\mathbf z)=\frac1{N_B}\sum_{i\in B}K(\mathbf x_i,\mathbf z)-\frac1{N_A}\sum_{i\in A}K(\mathbf x_i,\mathbf z)\). That is exactly the SVM form \(\sum_i\alpha_iy_iK(\mathbf x_i,\mathbf z)+b\) with all \(\alpha_i=1/N_{C}\) and \(b=0\). The SVM instead learns α (most become 0) and a bias b. Same kernel, same width parameter, different weights.

11SVM: advantages, disadvantages, conclusions slides 67–70

Why it works well in high-dimensional spaces

  • Class overlap is often not large there.
  • Minimising h minimises the risk of overfitting.
  • The classifier is determined by the support objects, not directly by the features.
  • No density is estimated.
Advantages
  • Generalises remarkably well, especially in high-dimensional spaces with relatively small sample sizes.
  • Given a kernel and C, there is one unique solution (convex QP).
  • The kernel trick allows a varying complexity.
  • The kernel trick allows specially engineered representations.
  • No strict data model is assumed (but when you can assume one, use it).
  • Solid theoretical foundation (when no slack variables are used).
  • An error estimate from training data only: \(\#SV/N\). It is loose, and you still need cross-validation for K and C.
Disadvantages
  • The quadratic optimisation is computationally expensive (specialised solvers exist).
  • The kernel and C have to be optimised.
  • Problems with highly overlapping classes (many objects become support vectors).

Conclusions (slide 70)
  • Always tune the complexity of your classifier to your data: number of training objects, dimensionality, class overlap, class shape…
  • Complexity is an elusive concept; the number of parameters is not sufficient.
  • VC-dimension is a complexity measure that takes a worst-case approach.
  • The support vector classifier tries to minimise its VC-dimension.

Exercise 1.1: maximum margin by hand

Class one: \((0,1)^T,(0,3)^T\). Class two: \((2,0)^T\). (a) Find the max-margin classifier geometrically; how many support vectors? (b) Move \((0,1)\) to \((0,-1)\). What changes?

You need: canonical hyperplane and margin (§5), the convex-hull shortcut (§5 box), support vectors and the α checks (§6). Verify with the playground presets (§7).

Hint

Draw the convex hull of class one (it's a line segment). Find the point of that segment closest to (2, 0). The perpendicular bisector of the closest pair is the max-margin boundary.

Show worked solution

(a)

  1. Hull of class one = segment from (0,1) to (0,3). The foot of the perpendicular from (2,0) onto the line x₁ = 0 is (0,0), which lies outside the segment. So the closest hull point is the endpoint (0,1), at distance \(\sqrt{2^2+1^2}=\sqrt5\).
  2. Boundary = perpendicular bisector of (0,1) and (2,0): through the midpoint (1, 0.5) with normal (2, −1): \[2x_1-x_2-1.5=0\qquad(\text{i.e. }x_2=2x_1-1.5)\]
  3. Canonical scaling (class two = +1): demand \(f(2,0)=+1\). The unscaled expression gives \(2\cdot2-0-1.5=2.5\) there, so divide everything by 2.5: \[\mathbf w=(0.8,\,-0.4)^T,\qquad b=-0.6\] Check: \(f(0,1)=-0.4-0.6=-1\) ✓, \(f(2,0)=1.6-0.6=+1\) ✓, \(f(0,3)=-1.2-0.6=-1.8<-1\) (beyond the margin).
  4. Margin width \(2/\|\mathbf w\|=2/\sqrt{0.8}=\sqrt5\approx2.24\), the full distance between the two closest points ✓.
  5. 2 support vectors: (0,1) and (2,0). (0,3) has α = 0. Dual check: \(\mathbf w=\alpha_1(2,0)-\alpha_2(0,1)\) with \(\alpha_1=\alpha_2\) (from \(\sum\alpha_iy_i=0\)) gives \(\alpha_1=\alpha_2=0.4\). And \(\sum\alpha_i=0.8=\|\mathbf w\|^2\) ✓.

(b)

  1. Hull of class one = segment from (0,−1) to (0,3). Now the foot (0,0) lies on the segment, so the closest point is (0,0) (not a data point!), at distance 2.
  2. Bisector of (0,0) and (2,0): the vertical line \(\mathbf{x_1=1}\). Canonical: \(\mathbf w=(1,0)^T,\ b=-1\).
  3. \(f(0,-1)=-1\), \(f(0,3)=-1\), \(f(2,0)=+1\): all three objects lie on the margin, so 3 support vectors. Dual: \(\alpha=(0.375,\ 0.125,\ 0.5)\) for \((0,-1),(0,3),(2,0)\); \(\sum\alpha_i=1=\|\mathbf w\|^2\) ✓.
  4. What happened: the margin shrank (√5 → 2), the boundary rotated to vertical, and the SV count went up from 2 to 3. The point (0,3) didn't move but became a support vector. Which objects are SVs depends on the whole geometry, not on each point individually. (The LOO bound #SV/N goes from 2/3 to 3/3.)

Exercise 1.2: the SVM is sensitive to feature scaling

Show (graphically) with 3 training objects and 1 test point in 2D that rescaling a feature changes the SVM's decision.

You need: the margin is a Euclidean distance (§5), so anything that changes distances changes which points are closest and how the bisector is oriented. Contrast: Fisher is scale-invariant (§11 table).

Hint

Reuse the Ex 1.1(a) set. Stretch feature 1 by a factor 3, solve the max-margin problem in the stretched space, then map the boundary back. Pick a test point between the two boundaries.

Show worked solution

Training set (from 1.1a): A = {(0,1), (0,3)}, B = {(2,0)}. Test point \(\mathbf z=(1.5,\,2.5)\).

Original features. From 1.1(a): \(f(\mathbf x)=0.8x_1-0.4x_2-0.6\). Then \(f(\mathbf z)=1.2-1.0-0.6=-0.4<0\), so z is assigned to class A.

Multiply feature 1 by 3. Training set becomes A = {(0,1),(0,3)}, B = {(6,0)}, and z becomes (4.5, 2.5). The closest hull points are still (0,1) and (6,0) (the foot (0,0) is still outside the segment). Bisector normal ∝ (6, −1), midpoint (3, 0.5); canonical:

\[\mathbf w'=\tfrac{2}{37}(6,-1)=(0.324,\,-0.054),\qquad b'=-0.946\]

\(f(\mathbf z')=0.324\cdot4.5-0.054\cdot2.5-0.946=+0.38>0\), so z is now assigned to class B.

In the original coordinates the new boundary is \(x_1\approx0.97+0.056\,x_2\), almost vertical, instead of \(x_2=2x_1-1.5\):

Why: the SVM maximises a Euclidean margin. Stretching x₁ makes horizontal distances count more, so the bisector of the closest pair rotates (and in general even the set of support vectors can change). Fisher would not change: \(S_W^{-1}\) rescales every direction by its own spread, so \(\mathbf w^T\mathbf x\) is invariant to rescaling features. Practical lesson: standardise features before training an SVM (or Parzen / kNN / NMC).

Why Fisher gives \(x_1\approx1\) in 1.1(a): class one has zero spread in x₁ and class two has a single point, so \(S_W=\begin{bmatrix}0&0\\0&2\end{bmatrix}\) (+10⁻⁵I). Its inverse is huge (10⁵) in the x₁-direction, so \(\mathbf w\approx(2\cdot10^5,\,-1)\), i.e. essentially only x₁ is used. The boundary goes through the midpoint of the means \(\tfrac12[(0,2)+(2,0)]=(1,1)\), giving \(x_1\approx1\). The SVM instead goes through the midpoint of the closest points (0,1) and (2,0).

The pattern
  • When every object is a support vector, Fisher and the SVM coincide. Then all margin constraints are equalities, \(\mathbf w^T\mathbf x_i+b=y_i\) for every i, which is exactly what least-squares Fisher solves (fisherc is "Fisher's least square linear discriminant"). (Checked numerically on 1000 random 3-point sets: every case with 3 SVs matched; cases with fewer SVs almost never did.)
  • As soon as some objects are not support vectors, they usually differ. Non-SV objects still shift Fisher's class means and scatter, but they have no influence on the SVM. Example: add a point far from the boundary. Fisher moves, the SVM does not.
  • Related: Fisher is scale-invariant and the SVM is not (Ex 1.2). Fisher models global class shape (means + covariance); the SVM only looks at the border region.

Exercise 2.1: the feature map behind the Gaussian kernel

For 1D objects x and χ, find φ with \(\phi(x)^T\phi(\chi)=\exp(-(x-\chi)^2)\). What is the dimensionality of φ's space?

You need: the idea \(K(\mathbf x,\mathbf y)=\Phi(\mathbf x)^T\Phi(\mathbf y)\) (§9), the polynomial-kernel trick of splitting a product into "something of x" times "the same thing of y" (§9), and the Taylor series \(e^u=\sum_{k\ge0}u^k/k!\).

Show worked solution

Step 1: expand the exponent. \(-(x-\chi)^2=-x^2+2x\chi-\chi^2\), so

\[e^{-(x-\chi)^2}=e^{-x^2}\,e^{-\chi^2}\,e^{2x\chi}\]

Step 2: Taylor-expand the cross term.

\[e^{2x\chi}=\sum_{k=0}^{\infty}\frac{(2x\chi)^k}{k!}=\sum_{k=0}^{\infty}\left(\sqrt{\tfrac{2^k}{k!}}\,x^k\right)\left(\sqrt{\tfrac{2^k}{k!}}\,\chi^k\right)\]

Step 3: give each factor its own x or χ part.

\[\boxed{\phi_k(x)=e^{-x^2}\sqrt{\tfrac{2^k}{k!}}\,x^k,\qquad k=0,1,2,\dots}\] \[\text{i.e. }\ \phi(x)=e^{-x^2}\left(1,\ \sqrt{\tfrac{2}{1!}}\,x,\ \sqrt{\tfrac{2^2}{2!}}\,x^2,\ \sqrt{\tfrac{2^3}{3!}}\,x^3,\ \dots\right)\]

Check: \(\phi(x)^T\phi(\chi)=e^{-x^2}e^{-\chi^2}\sum_k\frac{2^k}{k!}x^k\chi^k=e^{-x^2-\chi^2}e^{2x\chi}=e^{-(x-\chi)^2}\) ✓

(b) One coordinate per k = 0, 1, 2, …: φ maps a 1-dimensional x into an infinite-dimensional (countably infinite) space. This is why the RBF-SVM is so flexible, and why you can only use it through the kernel trick: you could never compute φ explicitly. (For a p-dimensional x the same argument gives infinitely many monomials too.)

Exercise 2.2: kernelising the nearest mean classifier

(a) Express the squared distance from test point x to a class mean in terms of inner products with the \(N_C\) samples \(\mathbf x_i^C\). (b) Kernelise with \(K(\mathbf x,\boldsymbol\chi)=\exp(-\|\mathbf x-\boldsymbol\chi\|^2/2\sigma^2)\). Show it boils down to something like a Parzen classifier (two classes).

You need: §10 (all three ingredients + the widget), Parzen density from earlier weeks: \(\hat p(\mathbf x\mid C)=\frac1{N_C}\sum_i\frac{1}{(2\pi\sigma^2)^{p/2}}\exp(-\|\mathbf x-\mathbf x_i^C\|^2/2\sigma^2)\).

Show worked solution

(a)

With \(\mathbf m_C=\frac1{N_C}\sum_{i=1}^{N_C}\mathbf x_i^C\):

\[\|\mathbf x-\mathbf m_C\|^2=\mathbf x^T\mathbf x-2\,\mathbf x^T\mathbf m_C+\mathbf m_C^T\mathbf m_C =\mathbf x^T\mathbf x-\frac{2}{N_C}\sum_{i=1}^{N_C}\mathbf x^T\mathbf x_i^C+\frac{1}{N_C^2}\sum_{i=1}^{N_C}\sum_{j=1}^{N_C}(\mathbf x_i^C)^T\mathbf x_j^C\]

Only inner products, so it can be kernelised.

(b)

Replace every inner product by K (this is the distance to the class mean in the feature space of K):

\[d_C^2(\mathbf x)=K(\mathbf x,\mathbf x)-\frac{2}{N_C}\sum_{i}K(\mathbf x,\mathbf x_i^C)+\frac{1}{N_C^2}\sum_{i,j}K(\mathbf x_i^C,\mathbf x_j^C)\]

For the Gaussian kernel, \(K(\mathbf x,\mathbf x)=e^0=1\). Define

\[\hat p_C(\mathbf x)=\frac1{N_C}\sum_iK(\mathbf x,\mathbf x_i^C)\qquad(\text{Parzen estimate with width }\sigma\text{, minus the constant }(2\pi\sigma^2)^{-p/2})\] \[c_C=\frac1{N_C^2}\sum_{i,j}K(\mathbf x_i^C,\mathbf x_j^C)\qquad(\text{does not depend on }\mathbf x)\]

Then \(d_C^2(\mathbf x)=1-2\,\hat p_C(\mathbf x)+c_C\). Two classes: assign x to A iff \(d_A^2<d_B^2\):

\[1-2\hat p_A+c_A<1-2\hat p_B+c_B\iff \boxed{\hat p_A(\mathbf x)-\hat p_B(\mathbf x)>\frac{c_A-c_B}{2}}\]

Compare the Parzen classifier (equal priors): assign to A iff \(\hat p_A(\mathbf x)>\hat p_B(\mathbf x)\), i.e. \(\hat p_A-\hat p_B>0\). The normalising constant \((2\pi\sigma^2)^{-p/2}\) is the same for both classes, so it doesn't change that comparison.

So the kernelised nearest mean classifier is a Parzen classifier with the same width σ, plus a constant offset \((c_A-c_B)/2\) in the decision. Interpretations:

  • \(c_C=\|\mathbf m_C^{\Phi}\|^2\) is the squared norm of the class mean in feature space. It is large for a compact class (objects similar to each other) and small for a spread-out class.
  • If both classes are equally compact (\(c_A=c_B\)), it is exactly the Parzen classifier.
  • Otherwise the offset favours the more spread-out class a little, much like a prior/threshold shift. The §10 widget shows it.
  • Nice consequence: Parzen = "nearest mean in an infinite-dimensional RBF feature space", i.e. a linear classifier there.

Exercise 2.3: RBF support vector classifier in prtools (coding)

(a) On a = gendatb([20,20]), train svc with an 'rbf' kernel for widths from ~0.1 to ~10; measure the error on a large independent banana test set. (b) How does the parzenc width relate to the RBF width? (c) Why can the svc be much faster than Parzen at test time?

You need: RBF width = complexity knob (§9), the σ-convention box (§9), SVM-vs-Parzen form (§10 box), sparsity of α (§6).

prtools syntax you'll use
  • w = pr.svc(a, ('rbf', sigma, C)): kernel type, kernel parameter, trade-off C (default C = 1).
  • err = pr.testc(b * w): error of trained classifier w on dataset b (or b * w * pr.testc()).
  • len(w.data.support_): number of support vectors (w.data is the underlying sklearn SVC).
  • pr.parzenc(a, h): pass a plain Python float. np.float64 values (e.g. from np.logspace) crash it with IndexError, because prtools checks type(x) is float. Use float(h).
  • pr.scatterd(a); pr.plotc(w): scatter plot + decision boundary.
Show code
a = pr.gendatb([20, 20])            # small training set (40 objects)
b = pr.gendatb([1000, 1000])        # large independent test set
sigmas = [0.1, 0.2, 0.5, 1, 2, 3, 5, 10]
C = 1.0

err_test, err_train, n_sv, err_parzen = [], [], [], []
for s in sigmas:
    w = pr.svc(a, ('rbf', s, C))
    err_test.append(pr.testc(b * w))
    err_train.append(pr.testc(a * w))
    n_sv.append(len(w.data.support_))
    # Parzen with the SAME kernel shape: exp(-d²/σ²) = exp(-d²/(2h²))  =>  h = σ/√2
    err_parzen.append(pr.testc(b * pr.parzenc(a, float(s / np.sqrt(2)))))

plt.figure(figsize=(6, 4))
plt.semilogx(sigmas, err_test, 'o-', label='svc test error')
plt.semilogx(sigmas, err_train, 's--', label='svc training error')
plt.semilogx(sigmas, err_parzen, '^-', label='parzenc test error (h = σ/√2)')
plt.xlabel('RBF width σ'); plt.ylabel('error'); plt.legend(); plt.grid(alpha=.3); plt.show()
print('support vectors:', n_sv)

Show answers to (a), (b), (c)

(a) Performance vs kernel width

  • Small σ (0.1–0.5): overfitting. Every training object gets its own tiny bump. Training error is 0, almost all 40 objects are support vectors, and the boundary is a set of little islands around objects of one class. Far from the training objects all kernel terms vanish and \(f(\mathbf z)\approx b\), so most of the test set lands in one class: error close to 0.5.
  • Intermediate σ (≈ 1–3): best. Smooth enough to generalise, flexible enough to follow the banana; test error ≈ 3–8 %.
  • Large σ (≥ 5–10): underfitting. Bumps are so wide the boundary is almost linear and cannot bend around the bananas: training and test error both rise.
  • So σ is the complexity parameter of the RBF-SVM. With only 40 training objects, the best choice is a fairly smooth classifier (the learning-curve rule from §1). In practice, pick σ (and C) with cross-validation.

(b) Parzen width vs RBF width

  • Both use a Gaussian kernel centred on training objects, and the width plays the same role (small = complex/local, large = smooth/global).
  • In prtools the formulas differ by a factor 2: svc uses \(\exp(-\|\mathbf x-\mathbf y\|^2/\sigma^2)\) (gamma = 1/σ²) and parzenc uses \(\exp(-\|\mathbf x-\mathbf y\|^2/2h^2)\). They are the same kernel when \(\sigma=\sqrt2\,h\) (i.e. \(h=\sigma/\sqrt2\)). The optimal values agree roughly: σ ≈ 2 ↔ h ≈ 1.4.
  • Structurally (§10): Parzen = \(\sum_i\alpha_iy_iK(\mathbf x_i,\mathbf z)\) with all \(\alpha_i=1/N_C\), b = 0. The SVM learns sparse α's and a bias b. That bias is why the SVM collapses for tiny σ while Parzen does not: Parzen just compares the two class sums, so the nearest object wins (1-NN behaviour).

(c) Why the svc can be much faster at test time

  • Parzen must evaluate the kernel between the test object and all N training objects: cost \(O(N\cdot p)\) per test object, and you must store the whole training set.
  • The SVM only needs the objects with \(\alpha_i>0\): \(f(\mathbf z)=\sum_{i\in SV}\alpha_iy_iK(\mathbf x_i,\mathbf z)+b\), cost \(O(\#SV\cdot p)\). Usually #SV ≪ N (USPS: ~150–200 SVs out of 7291 training digits), so it is much faster and needs much less memory.
  • Caveat (visible in the table): with a too-small σ or heavily overlapping classes, almost every object becomes a support vector and the speed advantage disappears.
