My warm-up answers

In my own words

Q: How does Goodfellow define regularisation?
Me (corrected): I said "reducing the number of parameters". That is only one way to regularise. The definition is: any technique that reduces the test error, possibly at the cost of a higher training error. The word "possibly" matters: a technique counts even if it makes the model more flexible, as long as test error goes down (see dropout, Part 8).

Q: What does L2 (weight decay) do to a weight at every gradient step?
Me: It multiplies the weight by a factor slightly below 1, $(1-\epsilon\alpha)$, so big weights shrink more in absolute terms. ✓

Q: Why does early stopping regularise (with small initial weights)?
Me: The weights haven't grown much yet, so $\|\mathbf w\|$ is still small and the network is still close to linear, i.e. simple. ✓

Q: Dropout keeps each node with probability $p$. What happens to the weights at test time?
Me (corrected): I wasn't sure. You multiply the weights by $p$. During training a weight is "on" with probability $p$ and "off" (0) otherwise, so on average the next layer saw $p\cdot w$. At test time all nodes are on, so scale by $p$ to give the next layer the same average input.

Big picture

A very flexible model trained on too little data fits the noise: training error goes down, test error goes up. Regularisation is the toolbox for trading a little training performance for better test performance. The lecture walks through that toolbox (Goodfellow ch. 7) and ends with the practical question: how do you know you need it?

1 · DetectLearning curve: gap between true error $\varepsilon$ and apparent error $\varepsilon_A$
→
2 · More dataAugmentation, adversarial examples (or fewer features)
→
3 · Penalise$\tilde J = J + \alpha\,\Omega(\boldsymbol\theta)$: L2, L1

4 · Training tricksEarly stopping, small init, noise, weight sharing, dropout
→
5 · Re-checkLearning curve again, without peeking at the test set
One sentence to remember

Most techniques work by keeping the weights small or few: the error bound for neural networks (Part 2) depends on the size of the weights, not on how many there are.

Part 1 — Overfitting and the learning curve slides 2–8

Intuition

Fit a polynomial $f(x)=w_px^p+w_{p-1}x^{p-1}+\dots+w_1x+w_0$ through a few points. Degree $p=1$ is too stiff to follow the curve (underfitting). Degree $p=2$ follows the trend (appropriate capacity). Degree $p=9$ passes through every point but swings wildly in between (overfitting). You prefer $p=2$, but the training error prefers $p=9$. The slide asks: how do you quantify that preference? Regularisation is the answer: write the preference into the loss.

See it live: Polynomial + L2 lab ↓

Learning curve: true vs apparent error

  • True error $\varepsilon$: error on new data from the same distribution (what you care about).
  • Apparent error $\varepsilon_A$: error on the training set. It is too optimistic, because the model was fitted to exactly these objects.
  • Plot both against the training set size $N$. The gap $\varepsilon-\varepsilon_A$ is overfitting. As $N$ grows both curves meet at the model's asymptotic error.

Different complexities and the Bayes error (slides 6–7)

  • "Where is underfitting?" In the asymptote. A simple model's error flattens out well above the Bayes error, even with infinite data. That leftover gap is bias you can't remove with more data.
  • "How does a very, very, very complex model look?" Apparent error stays at exactly 0 up to a huge $N$ (it can memorise everything). True error starts near chance level and only comes down for very large $N$. Its asymptote is close to the Bayes error, but you need an enormous training set to get there.

Formula
$$\text{overfitting} \approx \varepsilon(N) - \varepsilon_A(N), \qquad \text{underfitting} \approx \varepsilon_\infty - \varepsilon_{\text{Bayes}}, \qquad \varepsilon_A(N),\ \varepsilon(N) \xrightarrow{N\to\infty} \varepsilon_\infty \ \ge\ \varepsilon_{\text{Bayes}}$$

$N$: training set size · $\varepsilon_\infty$: the model's asymptotic error · $\varepsilon_{\text{Bayes}}$: the lowest error any classifier can reach.

In code
import numpy as np
rng = np.random.default_rng(0)

xt = rng.uniform(-1, 1, 1000); yt = np.sin(3*xt) + 0.2*rng.normal(size=1000)  # big test set
for p in [1, 3, 9]:
    w  = np.polyfit(x, y, p)                     # least squares, degree p
    tr = np.mean((np.polyval(w, x)  - y )**2)    # apparent error
    te = np.mean((np.polyval(w, xt) - yt)**2)    # estimate of the true error
    print(p, round(tr, 3), round(te, 3))

# 3 0.021 0.056
# 9 0.0   0.389

Part 2 — What "regularisation" means slides 9–14, 18–20

Intuition

Why bother? Because there is potential to improve performance: give up a bit of training performance to win more test performance. You keep the big, flexible model but stop it from using all of its flexibility on noise.

How to beat overfitting (slides 10–12)

  1. Use more data, e.g. data augmentation (Part 3).
  2. Reduce the number of features (Part 3).
  3. Reduce the complexity / flexibility of the model = regularisation in the narrow sense: discourage overly complex models. For neural networks: parameter norm penalties (Part 4), early stopping (Part 5), noise robustness (Part 6), weight sharing (Part 7), dropout (Part 8), …

Two definitions (slide 13)

SourceDefinition
Most textbooks"Regularisation is used to reduce overfitting."
Goodfellow"Regularisation are techniques to reduce the test error, possibly at the expense of increased training error."

The second definition also covers techniques that increase the model's flexibility. "Possibly" means the training error could even go down.

Formula: the regularised loss (slide 20)
$$\tilde J(\boldsymbol\theta;\mathbf X,\mathbf y) \;=\; \underbrace{J(\boldsymbol\theta;\mathbf X,\mathbf y)}_{\text{standard loss}} \;+\; \underbrace{\alpha}_{\text{reg. parameter}}\;\underbrace{\Omega(\boldsymbol\theta)}_{\text{regulariser}}$$

$\boldsymbol\theta$: all parameters · $J$: the usual loss (MSE, cross-entropy) · $\Omega$: a number that is large for "complex" parameters, e.g. $\|\mathbf w\|^2$ · $\alpha\ge 0$: how much you care. $\alpha=0$ means no regularisation; a large $\alpha$ forces a simple model. Same shape as week 5a: $\varepsilon_A(\theta)+\lambda\,\Omega(\theta)$, and the SVM's $\|\mathbf w\|^2 + C\sum\xi_i$.

Why penalise the size of the weights? A generalisation bound (slides 18–19)

For a neural network $h$ with input dimension $n$, $m$ training objects and $\ell$ layers, with probability $1-\delta$:

$$\mathrm{er}_P(h) \;<\; \widehat{\mathrm{er}}{}^{\gamma}_z(h) \;+\; \sqrt{\frac{c}{m}\left(\frac{B^2(AL)^{\ell(\ell+1)}}{\gamma^{2\ell}}\,\log n\,\log^2 m + \log(1/\delta)\right)}$$
SymbolMeaning
$\mathrm{er}_P$, $\widehat{\mathrm{er}}_z$test (true) error, training error with margin $\gamma$
$A$sum of the absolute values of the weights
$B$maximum norm of the data vectors
$L$smoothness of the activation function
$\ell$, $\gamma$, $m$number of layers, margin, number of training objects

Look at what is not in it: the number of weights. What matters is how large the weights are. For a two-layer network this reads: true error < train error + $f\big((\text{norm of weights})^3\big)$.

Tiny numbers: where the "³" comes from

Two layers: $\ell=2$, so $(AL)^{\ell(\ell+1)}=(AL)^6$. It sits under a square root, so the bound grows like $(AL)^3$. Double the total weight size $A$ and that term grows $2^3=8\times$. Halve it and it shrinks $8\times$. Meanwhile more data helps only like $1/\sqrt m$.

Watch out

Like the VC bound of week 5a, this bound is very loose and worst-case. Its value is the message: small weights = low complexity, even when there are millions of them.

Part 3 — More data: augmentation, adversarial examples, fewer features slides 15–17

Intuition

The best cure for overfitting is more data. If you know which changes don't change the label (a digit shifted 2 pixels is still the same digit), you can manufacture extra training objects for free.

Dataset augmentation (slide 15)

  • LeCun et al. (1998) trained a digit recogniser on randomly distorted copies of the training digits: horizontal and vertical translations, scaling, squeezing (squash one way, stretch the other) and horizontal shearing. The test error dropped.
  • Only possible when you know the invariances of the problem.
  • "No rotation? Why?" A likely reason: big rotations can change the class. Rotate a 6 by 180° and it is a 9. Augmentation must keep the label the same.
  • Songs? Small time shifts, slight tempo or pitch changes, added background noise, volume changes. Videos? Crops, flips, brightness changes, small shifts in time.

Adversarial data (slide 16)

Take an input $\mathbf x$ and nudge every pixel a tiny step $\epsilon$ in the direction that increases the loss the most:

Formula (fast gradient sign)
$$\tilde{\mathbf x} \;=\; \mathbf x + \epsilon\,\operatorname{sign}\!\big(\nabla_{\mathbf x} J(\boldsymbol\theta,\mathbf x,y)\big)$$

$\nabla_{\mathbf x}J$: how the loss changes when you change the input (not the weights) · sign: keep only the direction (+1 or −1) per pixel · $\epsilon$: step size per pixel.

With $\epsilon=0.007$ a "panda" (57.7% confidence) becomes a "gibbon" (99.3% confidence), and the change is invisible to us. Two ways to use this:

  • Generate samples that are correctly classified with high confidence (extra data).
  • Generate samples that are incorrectly classified with high confidence and add them, with their true label, as counter-examples (adversarial training). This forces the function to be smoother around the training data.
Tiny numbers: why tiny pixel changes add up

Linear score $f(\mathbf x)=\mathbf w^\top\mathbf x$ with $\mathbf w=(2,-1,0.5)$ and $\mathbf x=(0.3,0.2,0.2)$: $f = 0.6-0.2+0.1 = 0.5$, so class "+".

To push it down, step against the gradient: $\tilde{\mathbf x}=\mathbf x-\epsilon\,\operatorname{sign}(\mathbf w)$ with $\epsilon=0.2$. Every feature moves by only 0.2, but the score drops by $\epsilon\,\|\mathbf w\|_1 = 0.2\times 3.5 = 0.7$, to $-0.2$: the class flips. With 100 000 pixels, $\|\mathbf w\|_1$ is huge, so an invisible $\epsilon$ is enough.

Feature reduction (slide 17)

  • Fewer features means fewer weights and less room to overfit (covered in the Elements of Statistical Learning course: feature selection and extraction).
  • Currently a bit out of fashion.
  • Sometimes done "sneakily" in image classification by rescaling every image to 28×28: that throws away most of the pixels.

Part 4 — Parameter norm penalties: L2 (weight decay) and L1 slides 21–23

Intuition

L2 is a rubber band pulling every weight back towards 0. The pull is proportional to the weight, so big weights get pulled hard and small weights hardly at all: weights get smaller, rarely exactly 0.

L1 is a constant-strength pull towards 0, whatever the weight's size. A weight that the data only weakly needs gets pulled all the way to exactly 0. So L1 switches off features or neurons.

L2 regularisation = weight decay

Formula
$$\tilde J(\mathbf w) = \frac{\alpha}{2}\mathbf w^\top\mathbf w + J(\mathbf w) \quad\Rightarrow\quad \nabla_{\mathbf w}\tilde J = \alpha\mathbf w + \nabla_{\mathbf w}J$$ $$\mathbf w \leftarrow \mathbf w - \epsilon\big(\alpha\mathbf w + \nabla_{\mathbf w}J\big) \;=\; \underbrace{(1-\epsilon\alpha)}_{\text{decay factor}}\,\mathbf w \;-\; \epsilon\,\nabla_{\mathbf w}J$$

$\epsilon$: learning rate · $\alpha$: regularisation strength · $\mathbf w^\top\mathbf w=\sum_i w_i^2$. Each step first shrinks every weight by the factor $(1-\epsilon\alpha)$, then takes the normal gradient step. Same thing as ridge regression, Tikhonov regularisation, and weight decay (Hinton 1987).

Tiny numbers

$\epsilon=0.1$, $\alpha=0.5$ → decay factor $1-0.05=0.95$.

CaseUpdateResult

What L2 does to the solution (slide 23)

Without the penalty you would land at the training-loss minimum $\mathbf w^*$. With it you land at $\tilde{\mathbf w}$, where a contour of the loss just touches a circle of the penalty. Near $\mathbf w^*$ the loss is approximately a bowl with curvatures $\lambda_i$ (the eigenvalues of the Hessian $H$, the matrix of second derivatives). Then (derivation in the blueprint):

Formula
$$\tilde{\mathbf w} = (H+\alpha I)^{-1}H\,\mathbf w^* \qquad\text{diagonal } H:\quad \tilde w_i = \frac{\lambda_i}{\lambda_i+\alpha}\,w_i^*$$

Steep direction ($\lambda_i\gg\alpha$): factor ≈ 1, the weight is kept. Flat direction ($\lambda_i\ll\alpha$): factor ≈ 0, the weight is shrunk away. On the slide the loss ellipses are wide along $w_1$ (flat), so $\tilde{\mathbf w}$ loses most of $w_1$ but keeps $w_2$.

L1 regularisation (slide 22)

Formula
$$\tilde J(\mathbf w) = \alpha\|\mathbf w\|_1 + J(\mathbf w), \qquad \|\mathbf w\|_1=\sum_i |w_i|, \qquad \nabla_{\mathbf w}\tilde J = \alpha\,\operatorname{sign}(\mathbf w) + \nabla_{\mathbf w}J$$

(Strictly a subgradient: $|w|$ has a kink at 0.) The pull $\alpha\operatorname{sign}(w_i)$ has the same size for every weight. With a diagonal Hessian the solution is soft thresholding:

$$\tilde w_i = \operatorname{sign}(w_i^*)\,\max\!\Big(|w_i^*|-\frac{\alpha}{\lambda_i},\,0\Big)$$

Every weight with $|w_i^*|\le\alpha/\lambda_i$ becomes exactly 0. This performs feature selection / neuron removal during training. Compare Optimal Brain Damage (LeCun 1990): remove the weights with the smallest second-order influence on the error.

Tiny numbers: L1 vs L2 side by side

$\mathbf w^*=(2,\,1)$, curvatures $\lambda=(1,\,10)$ (flat in $w_1$, steep in $w_2$), $\alpha=2.5$:

$\tilde w_1$$\tilde w_2$
L2: $\frac{\lambda_i}{\lambda_i+\alpha}w_i^*$$\frac{1}{3.5}\cdot2 = 0.571$$\frac{10}{12.5}\cdot1 = 0.80$
L1: $\max(|w_i^*|-\alpha/\lambda_i,0)$$\max(2-2.5,0) = \mathbf{0}$$1-0.25 = 0.75$

L1 removes $w_1$ completely; L2 only shrinks it.

In code (NumPy, from scratch)
def ridge(X, y, alpha):
    """L2-regularised least squares: minimise ||Xw - y||^2 + alpha ||w||^2."""
    d = X.shape[1]
    return np.linalg.solve(X.T @ X + alpha * np.eye(d), X.T @ y)

def soft_threshold(w_star, lam, alpha):
    """L1 solution for a diagonal Hessian (curvatures lam)."""
    return np.sign(w_star) * np.maximum(np.abs(w_star) - alpha / lam, 0)

Part 5 — Early stopping and initialisation slides 24–36

Intuition

Start with small weights (a simple, almost linear network). Every gradient step makes the weights a bit bigger and the network a bit more flexible: training = slowly increasing the complexity. So when you stop is a complexity knob. Watch the error on a validation set and stop where it is lowest. You get the regularisation "for free": no penalty term, no extra parameters in the loss.

Early stopping (slide 24)

  • Stop the gradient updates prematurely. Instead of the global training minimum $\mathbf w^*$ you end at a regularised $\tilde{\mathbf w}$.
  • Started near the origin, the gradient-descent path to $\mathbf w^*$ passes through roughly the same points as the L2 solutions for decreasing $\alpha$. So early stopping behaves much like L2.
  • Training curve on the slide: training loss keeps falling to ≈0, while validation loss bottoms out early (around epoch 20) and then slowly rises.

Initialisation matters (slides 25–28)

  • Early stopping only helps when the network is initialised correctly.
  • Bad: a 5-layer tanh network with weights drawn uniformly from [0, 1] (large). The units saturate, the boundary stays a straight line through the two circles, and accuracy is stuck at ≈ 50% for 500 epochs.
  • Good: small initial weights. The network starts (almost) linear, then bends the boundary into a circle; train and test accuracy climb together to ≈ 0.83.

Watching a network train (slides 29–31)

  • 1-hidden-layer network on the banana set (30 objects per class). The boundary moves from the red line (start) to the green curve (end).
  • The training error curve shows plateaus and sudden drops.
  • The norm of the weights keeps increasing, from about 3 to over 8 in 10 000 iterations. Longer training means larger weights, a larger bound (Part 2), a more complex model.

Summary (slide 36)

If the weights are initialised so that the initial network is (almost) linear, and training is stopped in time, then the norm of $\mathbf w$ is not too large. You are not using the full potential of the network, your optimisation was "poor", the network is not fully (over)fitted on the training data, and you get better generalisation.

Formula: early stopping ≈ L2 (Goodfellow §7.8)
$$\alpha \;\approx\; \frac{1}{\tau\,\epsilon}$$

$\tau$: number of training steps · $\epsilon$: learning rate · $\alpha$: the equivalent L2 strength. More steps or a bigger learning rate means weaker regularisation. Example: $\epsilon=0.01$, $\tau=100$ gives $\alpha\approx1$. (Exact only for a quadratic loss, but the idea carries over.)

Part 6 — Noise robustness slides 37, 46

Intuition

If the model must give the same answer when its inputs, weights or targets are jiggled a bit, it can't rely on fine-tuned, fragile details. Noise forces a smoother, more stable solution.

Where you add noiseWhat it amounts to
InputData augmentation (Part 3). With infinitesimally small variance it is equivalent to weight-norm (L2) regularisation.
WeightsEncourages stability: prefer solutions where small weight changes don't change the output (flat minima).
Output (labels)Label smoothing: soft targets, e.g. 0.1 / 0.9 instead of 0 / 1 (slide 46).
Formula: input noise = L2 (linear model, derivation in the blueprint)
$$\mathbb E_{\mathbf e\sim\mathcal N(0,\sigma^2 I)}\Big[\big(\mathbf w^\top(\mathbf x+\mathbf e)-y\big)^2\Big] \;=\; \big(\mathbf w^\top\mathbf x-y\big)^2 \;+\; \sigma^2\,\|\mathbf w\|^2$$

$\mathbf e$: random noise added to the input · $\sigma^2$: its variance · $\mathbb E$: average over the noise. The noise adds exactly an L2 penalty with strength $\sigma^2$.

Label smoothing with $k$ classes and smoothing $\varepsilon_{ls}$: target $1-\varepsilon_{ls}$ for the true class and $\varepsilon_{ls}/(k-1)$ for the others.

Tiny numbers

$\mathbf w=(2,-1)$, $\mathbf x=(0.5,0.3)$, $y=0.4$, $\sigma^2=0.01$: residual $\mathbf w^\top\mathbf x-y = 0.7-0.4 = 0.3$, so $0.3^2 + 0.01\cdot(4+1) = 0.09+0.05 = \mathbf{0.14}$. A Monte-Carlo average over 100 000 noisy copies gives 0.1402.

Label smoothing, $k=10$, $\varepsilon_{ls}=0.1$: target 0.9 for the true class and $0.1/9\approx0.011$ for each other class. With hard 0/1 targets the cross-entropy keeps rewarding ever larger logits (so ever larger weights); with soft targets the optimum is finite.

In code
rng = np.random.default_rng(1)
w = np.array([2.0, -1.0]); x = np.array([0.5, 0.3]); y = 0.4; s2 = 0.01
e = rng.normal(0, np.sqrt(s2), size=(100_000, 2))     # 100k noisy copies of x
print(np.mean(((x + e) @ w - y)**2))                  # 0.1402  (noise, averaged)
print((x @ w - y)**2 + s2 * w @ w)                    # 0.14    (no noise + L2 penalty)

Part 7 — Parameter sharing / tying slide 38

Intuition

A convolutional layer slides the same small kernel over every position of the image. All those positions share one set of weights. That is a hard constraint ("these thousands of weights must be equal"), so the number of free parameters collapses. The lecturer's personal opinion: this is one of the main reasons deep learning is so successful now.

Tiny numbers: LeNet-5, first layer C1

Input 32×32 = 1024 pixels. Output: 6 feature maps of 28×28 = 4704 units. Kernel 5×5.

Layer typeCountParameters
Fully connected$1024\cdot4704 + 4704$4 821 600
Local 5×5 windows, no sharing$4704\cdot(25+1)$122 304
Convolution (shared kernels)$6\cdot(25+1)$156

About 31 000× fewer parameters than fully connected, for one layer. (This also answers slide 49's "how much is the number of weights reduced by weight sharing?" for C1.)

In code
n_in, n_maps, out, k = 32*32, 6, 28*28, 5
full   = n_in * n_maps*out + n_maps*out        # 4,821,600
local  = n_maps*out * (k*k + 1)                # 122,304
shared = n_maps * (k*k + 1)                    # 156
print(full, local, shared, full / shared)      # ... 30907.7

Part 8 — Dropout slides 39–45

Intuition

At every training step, switch off a random subset of the nodes and train the network that is left. No node can rely on any particular other node being there, so the network can't build fragile, co-adapted solutions. The lecturer sees it as a combination of weight decay and noise injection. He is not fond of the popular "bagging" explanation (training an ensemble of all $2^n$ sub-networks, slide 40).

The procedure

  1. Each training step: keep each node with probability $p$; set the others to 0.
  2. Backprop as usual on the remaining network.
  3. At evaluation time, either
    • simulate a few (≈20) networks with dropped-out nodes and average their outcomes, or
    • don't drop nodes but rescale the weights (slide 42): $$\mathbf w_{new} = \mathbf w_{org}\,P[\text{no dropout}] + \mathbf 0\,P[\text{dropout}] = \mathbf w_{org}\,p$$
Watch out: what is p?
  • Slide 39 drops a fraction 1−p; slides 40–41 drop a fraction p. The formula on slide 42 only works if $p$ = probability of keeping a node. That is also the convention of the original paper (Srivastava et al.: keep 0.5 for hidden units, 0.8 for inputs).
  • Software often uses the opposite: in PyTorch, p is the probability of dropping. It also uses inverted dropout: during training the kept activations are divided by the keep probability, so nothing needs rescaling at test time. Slide 41's "rescale other weights with p" is this idea.
  • In an exam answer, always say which convention you use.

Formula
$$m_j\sim\text{Bernoulli}(p),\qquad \tilde h_j = m_j h_j,\qquad \mathbb E[\tilde h_j] = p\,h_j \;\Rightarrow\; \mathbf w_{test}=p\,\mathbf w$$

$m_j$: random keep (1) / drop (0) switch for node $j$. Exact for the linear sum going into the next layer. After a non-linearity it is an approximation, which is why averaging ~20 sampled networks is the alternative.

Is it really true? (slides 43–45)

  • Srivastava et al. (JMLR 2014), MNIST with a large network, varying the training set size: with dropout the error is worse for small sets (N=100) and better for large sets.
  • The lecturer's reading: compare with the learning curves of Part 1. Worse at small N and better at large N is exactly the signature of a more complex model. "It's not regularising, it is increasing the complexity!"
  • A TU Delft reproduction (X. Zhao, MSc thesis 2021) found dropout better at every size, so dropout does seem to regularise (sometimes…).
  • Other experience: it works for wide networks, not for slim and deep ones; it is not very suitable for convolutional networks (alternatives: SpatialDropout, probabilistic weighted pooling, max-drop, cutout). Open question: why is weight decay not enough?

Returning to the main point (slide 47)

Intuition

When do you need regularisation? When you overfit. When do you overfit? Look at the learning curve (error vs training set size): a big gap between true and apparent error. Unfortunately learning curves are expensive: many trainings at different N, repeated a few times to see how stable the result is.

Warning! (slide 48)

  • Avoid looking at the test set too much. Every look influences your hyperparameter choices, so you overfit yourself to the test set.
  • Look at the test set only when you want to optimise for that specific dataset. Then you can't claim that the error you measured is the error you will get on a new dataset.
  • Beware of claims in the literature. They are not always true (see the dropout plots).

Handwriting blueprint

Write each step on paper first, then reveal it to check.

1 · From the L2 penalty to "weight decay"

  1. Start from the regularised loss: $\tilde J(\mathbf w)=\frac{\alpha}{2}\mathbf w^\top\mathbf w + J(\mathbf w)$.
  2. Gradient of the penalty: $\nabla\big(\frac{\alpha}{2}\sum_i w_i^2\big) = \frac{\alpha}{2}\cdot 2\mathbf w = \alpha\mathbf w$ (that is why the $\frac12$ is there).
  3. Total gradient: $\nabla\tilde J = \alpha\mathbf w + \nabla J$.
  4. Gradient-descent step: $\mathbf w\leftarrow\mathbf w-\epsilon(\alpha\mathbf w+\nabla J)$.
  5. Regroup: $\mathbf w\leftarrow(1-\epsilon\alpha)\mathbf w-\epsilon\nabla J$. Every step first shrinks all weights by the factor $(1-\epsilon\alpha)$, then takes the usual step.

2 · Where L2 moves the minimum

  1. Approximate $J$ near its minimum $\mathbf w^*$ by a bowl (the gradient is 0 there): $\hat J(\mathbf w)=J(\mathbf w^*)+\frac12(\mathbf w-\mathbf w^*)^\top H(\mathbf w-\mathbf w^*)$.
  2. Add the penalty and set the gradient to zero: $H(\tilde{\mathbf w}-\mathbf w^*)+\alpha\tilde{\mathbf w}=\mathbf 0$.
  3. Collect the $\tilde{\mathbf w}$ terms: $(H+\alpha I)\tilde{\mathbf w}=H\mathbf w^*$, so $\tilde{\mathbf w}=(H+\alpha I)^{-1}H\mathbf w^*$.
  4. If $H=\mathrm{diag}(\lambda_1,\dots,\lambda_n)$, each coordinate separates: $\tilde w_i=\frac{\lambda_i}{\lambda_i+\alpha}\,w_i^*$.
  5. Read it: $\lambda_i\gg\alpha$ (steep, important) → $\tilde w_i\approx w_i^*$; $\lambda_i\ll\alpha$ (flat, unimportant) → $\tilde w_i\approx0$. Never exactly 0 unless $w_i^*=0$.

3 · Why L1 gives exact zeros (one weight)

  1. Minimise $f(w)=\frac12\lambda(w-w^*)^2+\alpha|w|$ with $\lambda>0$. Assume $w^*>0$.
  2. For $w>0$: $f'(w)=\lambda(w-w^*)+\alpha=0$ gives $w=w^*-\alpha/\lambda$. This is only valid if it is positive, i.e. $w^*>\alpha/\lambda$.
  3. For $w<0$: $f'(w)=\lambda(w-w^*)-\alpha=0$ gives $w=w^*+\alpha/\lambda>0$: a contradiction, so there is no minimum on this side.
  4. If $w^*\le\alpha/\lambda$, neither side has a stationary point, so the minimum is at the kink $w=0$.
  5. Together: $\tilde w=\operatorname{sign}(w^*)\max(|w^*|-\alpha/\lambda,\,0)$, "soft thresholding". Small weights become exactly 0.

4 · Input noise equals an L2 penalty (linear model)

  1. Prediction on a noisy input: $\mathbf w^\top(\mathbf x+\mathbf e)$, with $\mathbf e\sim\mathcal N(\mathbf 0,\sigma^2 I)$. Loss: $\big(\mathbf w^\top(\mathbf x+\mathbf e)-y\big)^2$.
  2. Call the clean residual $r=\mathbf w^\top\mathbf x-y$. Then the loss is $(r+\mathbf w^\top\mathbf e)^2=r^2+2r\,\mathbf w^\top\mathbf e+(\mathbf w^\top\mathbf e)^2$.
  3. Average over the noise: $\mathbb E[\mathbf e]=\mathbf 0$, so the middle term disappears.
  4. Last term: $\mathbb E[(\mathbf w^\top\mathbf e)^2]=\mathbf w^\top\mathbb E[\mathbf e\mathbf e^\top]\mathbf w=\sigma^2\mathbf w^\top\mathbf w$.
  5. So $\mathbb E[\text{loss}]=r^2+\sigma^2\|\mathbf w\|^2$: training on noisy inputs = clean training + L2 penalty with strength $\sigma^2$.

5 · The dropout weight-scaling rule

  1. During training node $j$ outputs $m_jh_j$ with $m_j\sim\text{Bernoulli}(p)$: 1 (keep) with probability $p$, 0 (drop) otherwise.
  2. The next layer receives $z=\sum_j w_j\,m_j\,h_j$.
  3. Its average over the masks: $\mathbb E[z]=\sum_j w_j\,\mathbb E[m_j]\,h_j=\sum_j (p\,w_j)\,h_j$.
  4. At test time all $m_j=1$. To give the next layer the same average input, use $w_j^{test}=p\,w_j$ (slide 42).
  5. Equivalent alternative ("inverted dropout"): divide by $p$ during training, $m_jh_j/p$, so $\mathbb E=h_j$ and test-time weights stay unchanged.

Exam traps

Watch out
  • "Regularisation means reducing the number of parameters." Too narrow (my warm-up mistake). Goodfellow: anything that lowers the test error, possibly raising the training error. The course exam review phrases its purpose as "penalising complex models".
  • "L2 sets unimportant weights to exactly zero." False. L2 multiplies them by $\lambda/(\lambda+\alpha)$; L1 gives exact zeros.
  • "With weight decay every weight gets smaller every step." Not necessarily. The shrink is followed by the normal gradient step, which can make an important weight grow. Only weights the data doesn't need decay towards 0.
  • "Training longer always gives a better network." No. The training optimum is not the test optimum (weight-space slides 32–35); that is why early stopping works.
  • "Early stopping works with any initialisation." No. It needs small initial weights so the network starts (almost) linear. Large weights saturate tanh and the network gets stuck.
  • Learning curve ≠ training curve. Learning curve: error vs training set size. Training curve: loss vs epochs. The exam review asks which question a learning curve can't answer: "How many epochs do we need?"
  • Dropout's $p$. The slides use both "drop 1−p" and "drop p"; the test-time rule $\mathbf w\,p$ needs $p$ = keep probability. PyTorch's p is the drop probability and it rescales during training instead. State your convention.
  • Forgetting the test-time rescaling. With all nodes on and no rescaling, the next layer gets inputs about $1/p$ times too large (2× for $p=0.5$).
  • "Dropout always regularises." The lecturer's point: in the original paper's plot dropout is worse for small N and better for large N, which is what a more complex model looks like.
  • Number of weights is not complexity. The neural-network bound depends on the size of the weights ($A$), not on how many there are (also week 5a: $\operatorname{sign}(\sin\omega x)$ has one parameter but infinite VC-dimension).
  • "Overfitting can be reduced by increasing the size of the dataset." TRUE (exam review).
  • Augmentation must keep the label. Rotating a 6 by 180° gives a 9.
  • Tuning on the test set. Every peek influences your choices; the test error is then no longer an honest estimate of the error on new data.

Self-check

Say your answer out loud or write it down before opening. Questions 7–11 are the lecturer's own "questions to think about" (slides 49–50).

1. Weight decay by hand: $\epsilon=0.1$, $\alpha=0.2$, $w=1.5$, $\partial J/\partial w=-0.5$. What is the new $w$?
Decay factor $1-0.1\cdot0.2=0.98$. New $w = 0.98\cdot1.5-0.1\cdot(-0.5) = 1.47+0.05 = \mathbf{1.52}$. The weight grew: the data gradient beat the decay.
2. One weight with curvature $\lambda=4$, unregularised optimum $w^*=0.3$, $\alpha=2$. Where does it end up with L1? With L2?
L1: threshold $\alpha/\lambda=0.5>0.3$, so $\tilde w=\mathbf 0$ exactly. L2: $\frac{4}{4+2}\cdot0.3=\mathbf{0.2}$, smaller but not zero.
3. Multiple choice: which of these is NOT a regularisation technique in the sense of this lecture? (a) dropout (b) early stopping (c) increasing the learning rate until training error is 0 (d) data augmentation
(c). Driving the training error to 0 is the opposite: it uses all of the model's flexibility. (a), (b) and (d) all aim to lower test error at the cost of some training performance.
4. In the dropout simulator's network, $\mathbf w^\top\mathbf h = 1.5$. With keep probability $p=0.8$, what should the test-time output be, and what would you get if you forgot to rescale?
Rescaled: $0.8\cdot1.5=1.2$, which matches the average the next layer saw during training. Forgetting: $1.5$, i.e. $1/0.8 = 1.25\times$ too large.
5. Exam-style code (from scratch, no autograd): the training loop updates layer.weight -= lr * layer.weight_grad. Change it so it uses L2 weight decay with strength alpha.
layer.weight -= lr * (layer.weight_grad + alpha * layer.weight), which is the same as layer.weight = (1 - lr*alpha) * layer.weight - lr * layer.weight_grad. The bias is usually left un-decayed: shifting the boundary doesn't make the model more flexible.
6. Srivastava's dropout plot: with dropout the error is higher at N = 100 but lower at N ≥ 5000. What does the learning-curve picture of Part 1 say about that?
That pattern (worse with little data, better with lots of data) is how a more complex model behaves, not a regularised one. Hence the lecturer's "it's not regularising, it is increasing the complexity!"
7. Do you need regularisation when you have an infinite amount of training data?
No. As $N\to\infty$ the apparent error equals the true error, so there is no overfitting gap left to close. Regularising would only push you away from the best model in your family (adding bias).
8. How can you know that you have to regularise less?
When you underfit: training (apparent) and validation error are both high and close together, and the learning curve converges to a level well above what a more flexible model reaches. Lowering $\alpha$ (or training longer, less dropout) then lowers the validation error.
9. Is the goal of optimising a network to reach the global optimum?
Not of the training loss. The global training optimum is the most overfitted solution (weight-space slides: training and test optima are in different places). The goal is low true error, which a deliberately "poor" optimisation (early stopping from a small init) can reach better.
10. Do you have to change the regularisation if you change your loss function?
Yes. $\tilde J=J+\alpha\Omega$ is a balance, so the right $\alpha$ depends on the scale of $J$: sum vs mean over samples, MSE vs cross-entropy, number of outputs. Change $J$ and you have to re-tune $\alpha$.
11. If the bound grows with $\|\mathbf w\|_1^3$, why not use $\|\mathbf w\|_1^3$ as the regulariser?
Some arguments: the bound is extremely loose, so its exact shape isn't something to optimise. Limiting $\|\mathbf w\|_1\le c$ is the same constraint as $\|\mathbf w\|_1^3\le c^3$, so you get much the same family of solutions; since you tune $\alpha$ anyway, the simplest penalty wins. And the cubic has an awkward gradient: almost zero near the origin, huge far away.
12. Does the learning rate influence the complexity of a network? And how does initialisation regularise?
Learning rate: yes, indirectly. With a fixed number of steps, $\alpha\approx1/(\tau\epsilon)$: a smaller learning rate travels less far from the init, like stronger L2. Initialisation: small init starts the network near-linear and near $\mathbf w=\mathbf 0$; the path from there, stopped in time, stays close to it, much like an L2 penalty centred at the init.
